# RC8 组网设备与路由展示方案

状态：用户已批准施工，页面及 RC8 版本修改已完成，并通过必要本地验证。软件内版本为 `2.0.0-rc8`，Flutter 构建号为 77；Windows 文件版本带 `+77` 构建元数据。交付 RC 压缩包，源码提交并推送到自有远程仓库。

## 目标

在一个列表中回答三个问题：到某个设备当前默认选路是直连还是中继、经过哪个设备、延迟如何。不再要求用户切到另一张路由表，或凭 IP 查找下一跳名称。

现有 EasyTier v2.6.4 CLI 的 peer/route JSON 已包含大部分所需字段。当前项目丢弃了部分字段，且把节点与路由分开展示；优先补齐现有查询的解析和关联，不增加组网进程或改变选路算法。

## 页面组织

保留上方方案选择、配置、启停区域。下方原「节点／路由」切换合并为「组网设备」，统一采用与首页设备框相同风格的圆角卡片，不使用表格。

顶部提供设备总数、当前直连数、当前中继数、路径未知数及刷新时间。搜索设备名/IP，按全部、直连、中继筛选；默认不引入复杂拓扑图。

卡片信息示意（名称与数字仅为布局样例）：

```text
╭─────────────────────────────────╮
│ 电脑图标  家中电脑          连接图标 │
│          10.10.98.150            │
│          中继 · 2 跳    ≈ 48 ms   │
│          经 香港节点        详情 › │
╰─────────────────────────────────╯
```

- 第一层：设备图标、设备名、虚拟 IP、右侧连接图标。延续首页的视觉语言，连接图标仍只填入 IP。
- 第二层：直连／中继／路径未知标签及延迟。直连示例为「直连 · UDP / 12.3 ms」；中继为「中继 · 2 跳 / ≈ 48 ms」。
- 第三层：中继设备直接显示「经 香港节点」，无需打开详情才能知道走谁。宽度足够时同时显示下一跳 IP；窄屏把下一跳 IP 放入详情，保留设备名。下一跳无名称时显示 IP。
- 点击组网页卡片或详情入口打开路由详情。连接图标是独立操作，点击不能同时触发详情。首页、设备页既有点击填 IP 的行为不随组网页改变。

布局根据可用内容宽度切换，不按操作系统区分：手机和窄窗口单列，宽桌面最多双列；不增加第三列来挤压设备名和路径。卡片高度随内容增长，长名称和较大系统字体可以换行，不固定卡片高度，不用 FittedBox 缩小字体，也不要求横向滚动。

使用已有瓷白／淡紫配色、圆角边框和图标。直连、中继、未知都用文字和图标标记，颜色仅作辅助。选中／展开项使用已适配的 surfaceContainerHighest 与 onSurface，避免再次出现黑底黑字。

## 手机屏幕与后续 Android 适配

卡片以手机单列布局为基础，再扩展为桌面双列。默认仅展示设备、IP、路径类型、延迟和下一跳名称，不把丢包、收发量、NAT、版本和子网同时塞入主卡片。

- 手机顶部显示紧凑的运行状态、当前方案和主启停操作；方案管理等次要操作收进菜单或弹层，不把桌面按钮横排挤入手机。桌面现有方案管理区域保留。
- 搜索框占一行，筛选支持换行或紧凑选择控件。统计信息可以换行，不放四张固定宽度的大统计卡。
- 手机详情使用可滚动的底部面板，可向上展开至接近全屏；窄窗桌面可用同样布局。宽桌面使用详情面板。两种外观共用同一份详情内容。
- 路径在手机详情中纵向展示「本机 → 中继节点 → 目标」，下一跳名称、IP、链路延迟分别可读，不用超长横向箭头链。
- 交互控件保持足够的触控面积（目标不小于 48 个逻辑像素）；图标使用工具提示或可访问性标签，状态不只靠颜色区分。
- 尊重安全区域、系统文字缩放和输入键盘。使用一个主纵向滚动容器，避免把设备列表塞进固定小高度的嵌套滚动区。
- 停止组网、没有设备、查询失败和旧数据均使用清晰的空状态／提示，不能靠空白或极小字体表达。

本次共享展示组件接收设备数据与操作回调，不直接依赖 Windows API、CLI 启动或桌面窗口控制。Android 后续可以通过自己的组网后端向同一组件提供数据；本方案中的响应式界面不等于已完成 Android 的组网权限、后台运行和后端适配。

## 状态和延迟含义

### 当前路径

按当前方案的选路策略，选择最少跳数或延迟优先的路由字段。延迟优先字段缺失或无效时，明确回退到可用路由，保留所用策略的信息。

- 有效路径为 1 跳且下一跳标记直连：显示「直连」。这里表示无需其他 EasyTier 节点转发，不承诺一定由 NAT 打洞建立。
- 有效路径大于 1 跳：显示「中继 · N 跳」，同时直接显示下一跳设备名及 IP。
- 数据缺失、互相矛盾或本轮查询失败：显示「路径未知」或过期提示，不默认当作直连。
- UDP、TCP、QUIC 是隧道协议，不能用来判断是否经过中继。没有对应链路的协议数据时不猜测。

存在直连链路但延迟优先选择中继时，主行仍显示「中继」，详情另显示「直连链路可用，但当前策略选择中继」。这是两个不同信息，不能把「存在直连」误报为「当前经直连转发」。

该状态描述当前查询到的选路结果，不作为某条远控连接实时流量逐包走向的抓包结论。

### 延迟

- 直连：使用对应直连链路的已上报延迟。
- 中继：主行显示所选路由的「路径估计延迟」，以 ≈ 标识；不得称为端到端实测 RTT。
- 展开详情同时显示「本机 → 下一跳」的直连延迟，便于判断中继入口的质量。
- 缺失或无效数值显示 —；不把 CLI 的未知默认值当作真实 0 ms。
- 不新增主动 Ping 探测或后台高频测速，沿用现有刷新周期。

## 展开详情

每台设备的详情集中显示：

1. 当前选路策略、跳数和路径示意。
2. 直连时：本机 → 目标；中继时：本机 → 下一跳名称（IP）→ 目标。超过两跳且没有完整链路证据时，用「…」表示未知中间节点，不拼造完整路径。
3. 路径估计延迟、到下一跳的直连延迟；存在备用直连链路时显示其延迟与协议。
4. 该设备发布的代理子网，作为设备下的可展开路由信息，不与设备列表重复计数。
5. 可获取时提供丢包、累计收发量、NAT 类型和版本作为次要信息；没有可靠数据就不显示，不将累计字节数标成实时速率。

「填入 IP」继续只负责填写远控地址，不自动连接，不探测对方是否安装 SubnetDesk。

下一跳优先显示路由返回的 hostname，并关联节点名称；两者缺失时退回 IP。设备重名时用 IP 区分。地址关联统一处理 CIDR 表示，避免 `10.x.x.x/24` 与 `10.x.x.x` 无法匹配。

## 数据与实现边界

- 保留现有受管 core、CLI、RPC 地址与实例校验方式。
- Rust 层保留 peer id、直连统计、设备名，以及路由的目标名称、两种策略的下一跳、跳数和延迟。不要过早把名称丢弃或将设备路由与代理子网展开成不可关联的扁平行。
- 先以 peer id 关联；CLI 某张表无 peer id 时使用规范化后的设备虚拟 IP。hostname 只用于显示，不能作为唯一键。
- 所选路径、直连链路和数据有效性分别保存；不能通过是否有 protocol 字段推断 P2P，也不能把最少跳数字段直接当作延迟优先的最终路径。
- peer/route 查询仍是现有的顺序查询，不宣称原子快照；若一次刷新出现关联矛盾，展示未知并等待下一轮，避免用旧数据强行拼接。
- 首页、设备页和组网页继续共用 EasyTierController 快照。新增字段采用兼容方式，既有填 IP 与来源 IP 限制不依赖这些展示标签，也不扩大允许来源集合。
- 主改动范围：`src/easytier/engine.rs`、`flutter/lib/common/widgets/easytier_console.dart`，以及同目录中的共享设备卡片／详情组件。展示组件不自行发起后台查询，控制器和已有设备列表只做必要字段接入。

## 施工与验收顺序

1. 用户确认此方案后，补齐 CLI 字段解析与关联，先完成状态/路径/延迟语义。
2. 实现统一设备卡片、详情及筛选，保持桌面当前方案管理区域及联机语义；共享组件先满足手机单列，再扩展桌面双列。Android 组网后端不在此次施工范围内。
3. 必要定向检查：普通直连、中继、直连可用但延迟优先走中继、下一跳缺名称、CIDR 地址关联、未知/失败数据；在 320／360／412 逻辑像素窄屏和宽桌面检查长名称、较大文字、列表滚动、详情滚动及连接按钮触控，不为此启动真实 Android 组网。
4. 构建实测版本；本机遮罩等与本次无关功能不重复测试，不为了验证而启动真实组网实例。
5. 新版功能定稿时统一修改 Rust、Flutter 和实际 Windows 显示版本为 `2.0.0-rc8`，再构建 RC8。若需要发布到 GitHub Releases，另按用户发布指令执行。
